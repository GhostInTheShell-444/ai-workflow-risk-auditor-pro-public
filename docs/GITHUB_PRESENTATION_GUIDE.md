# GitHub Presentation Guide

## Presentation order

1. Project name, one-sentence local-first positioning, public source-available status, and hero screenshot.
2. Cross-platform quick start.
3. Privacy-reviewed English product gallery.
4. Problem, implemented capabilities, and explicit non-capabilities.
5. Deterministic scoring and local-first boundaries.
6. Architecture, tests, synthetic examples, and detailed documentation.
7. Separate French and Hebrew RTL presentation.
8. Security, contribution, roadmap, release-checklist, and license links.

## Accuracy rules

- Describe findings as detected attention points, not proof.
- Describe scores and confidence as deterministic heuristics, not probabilities.
- Describe controls as recommendations and reductions as simulations.
- State that saving is explicit and SQLite is not encrypted by the app.
- Keep optional Ollama separate from authoritative deterministic results.
- Describe local AI as a bounded reviewer assistant, not score authority.
- Describe selected controls as hypothetical until implementation evidence is reviewed.
- Do not call the project production-grade, certified, or legally compliant.
- Use synthetic or appropriately anonymized examples only.

## Repository metadata and launch controls

Use [GitHub Repository Setup](GITHUB_REPOSITORY_SETUP.md) for the approved description, topic list, public repository identity check, and social-preview requirements. Use the [Public Release Checklist](PUBLIC_RELEASE_CHECKLIST.md) for ongoing publication verification.

Do not change visibility, create a tag, or create a release during documentation review.

## Visual command-center presentation

The README may describe the product as a “local-first AI risk command center” and may show the risk cockpit, evidence cards, simulation comparison, controlled Local AI module, dark/light themes, and optional desktop launcher.

Do not publish refreshed screenshots until they pass the synthetic-data, path, identity, metadata, and visible-pixel review in the screenshot documents. The existing gallery is stale relative to the current visual redesign and should be replaced only after owner visual approval.

Desktop-launcher wording must remain precise: Linux is supported first; Windows and macOS helpers are provided; macOS was not tested in this implementation pass; no package, release, system service, or hosted edition is implied.
